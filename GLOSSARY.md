# Glossary

Terms this fork uses in a sense of its own, and a few outside terms worth
having at hand. Upstream sherpa-onnx vocabulary keeps its upstream meaning.

| term | definition | topic / refs |
|---|---|---|
| auxiliary alignment retention | Keeping a prefix that has left the hypothesis beam alive in the CTC recurrence, under its own budget, so its later emissions still add probability to surviving descendants. Planned for a later pass. | [sketches](topics/beam-search-and-scorer-fusion.sketches.md#auxiliary-alignment-retention) |
| beam-search-and-scorer-fusion | Efficient phone and server ASR inference with LM fusion, using shared search components, model-specific execution, and independently weighted scorers. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md) |
| bulk-decoding | Decoding many recordings with `sherpa-onnx-offline-parallel`: length-sorted, bounded batches, attributable results, model and search threads sized apart, and a check that none of this changes a transcript. | [bulk-decoding](topics/bulk-decoding.md) |
| characterization test | A test that passes while a known defect is present and fails, with instructions, once the defect is fixed. | [overcount gap](gaps/streaming-ctc-trailing-blank-overcount.md) |
| chunked encoding, encoder windows | Encoding an utterance longer than `--encoder.window.seconds` in overlapping windows of a whole-utterance encoder and joining their outputs per output frame before one search. Not a streaming model's chunk-and-cache protocol. | [chunked-encoding](topics/chunked-encoding.md) |
| early partial-score beam | The pruning threshold applied to token extensions after only part of a scorer's charge is known, such as a character LM's first-character score. Separate from the hypothesis beam. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#proposed-adjustable-beam-for-partially-scored-expansions) |
| ER2 | A versioned, language-specific normalized error rate computed by a scorer that is not part of this repository; not plain WER. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md) |
| gather, state gather, gather source | Building an LM step's input states from its nodes' parents. Each parent's state is a row of an earlier step's output (a source); on the GPU a small graph concatenates the sources and picks the rows, nesting when there are more than eight sources. On the CPU the rows are copied on the host. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#execution-placement-and-batching) |
| honest search | A decode in which a supplied reference is observed and scored but changes no expansion, ranking, pruning, or result. Contrasts with reference-preserving search. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#reference-and-oracle-exploration-modes) |
| hypothesis beam | The retained set of distinct output prefixes, limited by a count (`--max-active-paths`) and by a score gap below the best (`--score-beam`). | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#options) |
| inflight batching | Admitting, finishing, and cancelling individual utterances while others in the same decoder stay active, with ready work batched across them. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#inflight-batching) |
| json-option-collections | Configure a vector of option structs through indexed command-line paths such as `--scorer.1.weight`, and through JSON that maps onto the same paths, using each struct's ordinary `Register(ParseOptions*)`. | [json-option-collections](topics/json-option-collections.md) |
| language-bindings | How the fork's options reach every language binding: typed C fields, an `options_json` object of command-line options applied after them, `literal_zeros` for exact zeros, and mirroring a new option everywhere when it is added. | [language-bindings](topics/language-bindings.md) |
| litert-backend | Running a recognizer's model through LiteRT's `.tflite` form so a phone's accelerator can run it; built for offline w2v-BERT CTC models. | [litert-backend](topics/litert-backend.md) |
| LM node | A recurrent-LM scorer's record of one unit history in one utterance: its last unit and, once computed, a row of an LM step's output holding the state after that unit (where the model runs, on the GPU for a GPU scorer) and the next-unit log probabilities (on the host). A hypothesis's scorer state points to one; hypotheses with the same history share it. It is computed only when a unit is scored after it. | [recurrent-lm-scorer.h](sherpa-onnx/csrc/recurrent-lm-scorer.h) |
| LM step | One run of a recurrent-LM scorer's model over a batch of LM nodes: from each node's unit and its parent's state to its state and next-unit log probabilities. Its width is the number of nodes, bounded by `max-batch` and `max-batch-mb`. A step's output lives while any of its nodes does. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#execution-placement-and-batching) |
| LODR | Low-order density ratio: during LM fusion, also subtract the score of a low-order LM (usually a bigram over the recognizer's tokens) estimated from transcripts like the recognizer's training text. It is an attempt to undo the text prior the recognizer itself learned, so that the external LM is not counted on top of it; it is aimed at transducers and attention decoders, whose decoders model text. Upstream applies it as `--lodr-fst` with a negative scale. Here it needs no mechanism of its own: fusion takes several scorers, and LODR is a second scorer with a negative weight. | [tuning sketch](gaps/sketches/fusion-parameter-tuning.md#a-parameter-to-include-subtracting-a-transcript-lm); [Zheng et al. 2022](https://arxiv.org/abs/2203.16776) |
| max-alignment mode | CTC search that scores an output by its single best alignment and, among hypotheses with the same last token, word state, and scorer state bytes, drops each one that another matches or beats in both its blank and nonblank endings. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#max-alignment-mode) |
| scorer | A pluggable model that adds a log score to a hypothesis as its output grows: an LM, or anything with the same state-and-advance contract. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#scorer-interface) |
| scorer state | A fixed number of bytes per hypothesis per scorer, owned by the decoder. The scorer declares the size and optional copy and destroy functions; an n-gram's bytes are its context, a recurrent LM's hold a reference to its own storage. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#scorer-interface) |
| scorer unit | The symbol a scorer consumes one at a time: a recognizer token, a character, or the scorer's own token. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#scorer-interface) |
| scorer wave | One call of a scorer's `Advance` within a frame: the extensions of every utterance in the search call whose next scorer unit is ready to score. A token of k scorer units takes k waves, each after the last, so later waves hold only the longer tokens. For a recurrent LM a wave becomes one LM step, or several when it exceeds the step limit. | [scored-prefix-trie.h](sherpa-onnx/csrc/scored-prefix-trie.h) |
| sum-over-alignments mode | CTC prefix search that scores an output by the summed probability of all its alignments, keyed by token sequence. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#search-semantics) |
| survival-requirement trace | For one hypothesis, the widest value each pruning limit would have needed at any step to keep it. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#conceptual-search-policy-tuning-support) |
| utterance | One logical decoding input with its own search state, scorer context, weights, and results, identified by a stable handle independent of batch position. | [beam-search-and-scorer-fusion](topics/beam-search-and-scorer-fusion.md#decoder-lifecycle) |
